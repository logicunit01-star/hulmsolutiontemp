## 7. Follow-up pass (2 Oct, evening): technical polish and draft policies

**Performance:**
- Google Tag Manager, and the jQuery it is loaded with, now loads after the page has finished loading and the browser is idle, instead of during the first render.
  - Events pushed earlier are kept in the `dataLayer` and sent once GTM loads. Checked in a browser: the GTM script, jQuery and the `gtm.js` event all still load.
- Lighthouse mobile, before → after (local build):
  - Homepage: performance 67–88 → 85–91. Largest contentful paint 4.6 s → 2.9 s.
  - Karachi page: 82 → 92.
  - Inventory page: 70 → 81.
  - Accessibility 100 and SEO 100 on all pages tested. Best practices 96.
  - Scores vary run to run on this test machine; the trend is consistent.
- The remaining Lighthouse suggestion is about 50 KB of unused JavaScript per page:
  - About 29 KB is the Next.js framework code, which can't be removed.
  - About 21 KB is jQuery. Check the GTM container (GTM-TMMQ565S): if no Custom HTML tag uses `$` or `jQuery`, remove the jQuery import from `src/components/analytics/google-tag-manager.tsx` and the `jquery` package.

**Images:**
- The non-blog pages use small images (17–94 KB).
- The heavy files, the 1.5–2 MB JPG/PNGs, are in `public/wp-content/uploads/`. Requests to `/wp-content/*` already redirect to `/images/uploads/`, so those files are never served and can be deleted to slim the deploy.
- Blog images were left as they are, because blogs stay byte for byte.

**Unused components:** `src/components/industries/industries-form.tsx` is not imported anywhere. It is a form that only shows "Thank you" and sends nothing. `src/components/home/DashboardCarousel.tsx` is also unused. Add both to the delete list.

**Internal links:** About now has 3 body links (adds one from the Book a demo page and one from the Karachi FAQ). The cookie policy is linked from the privacy policy and the footer, which is normal for a legal page.
